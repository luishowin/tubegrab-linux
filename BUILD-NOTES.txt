TubeGrab UI/build notes
=======================
Last updated: 2026-11-08
Branch: main
Version: 1.3.0

Purpose
-------
This note records how the Apple-like Tkinter interface was rebuilt, what broke
along the way, and the rules future builds should follow so the same visual and
input problems are not reintroduced.

1. Text antialiasing depends on the Tk build
--------------------------------------------
Symptom:
  All text was pixelated even though the app used scalable fonts.

Cause:
  The installed launcher was using a Python whose bundled Tk was built without
  Xft. Tk fell back to core X11 bitmap fonts.

Checks:
  python3 - <<'PY'
  import tkinter as tk
  root = tk.Tk()
  root.withdraw()
  print(root.tk.call("::tk::pkgconfig", "get", "fontsystem"))
  root.destroy()
  PY

  "xft" = antialiased text
  "x11" = pixelated text

Fix:
  - install.sh probes each candidate interpreter and prefers "xft".
  - The generated launcher uses the chosen absolute interpreter path.
  - The app logs a warning if a non-Xft Tk is used.

Rule:
  Never assume a Python with tkinter also has a good Tk. Probe fontsystem.
  Prefer the distro python3-tkinter build on Fedora.

2. Tk Canvas has no antialiasing
--------------------------------
Symptom:
  Rounded cards/buttons and circles had jagged edges.

Cause:
  Canvas create_polygon/create_arc/create_oval are not antialiased.

Fix:
  "widgets.py" generates small corner tiles as PhotoImages with 6x6
  supersampling. Each tile is pre-blended with the known background colour so
  it can be drawn opaquely. Corner tiles are cached per
  (radius, fill, border, background, border width).

Straight edges are ordinary Canvas lines. Only the corners are images.

Rule:
  Do not use Canvas polygons/arcs for visible curves.
  Use background-blended AA corner tiles (or a full-size rendered image for
  very small controls).

3. Nested rounded surfaces need the underlying colour
-----------------------------------------------------
Symptom:
  Focus rings and selected segmented-control thumbs showed dark/light notches
  at the corners.

Cause:
  A rounded surface drawn on top of another surface was still blending its
  corner tiles against the window background instead of the surface below.

Rule:
  When drawing surface B on surface A, pass A's colour as B's background:
    - URL focus ring -> inner field background = ring colour
    - segmented thumb -> background = seg_track
    - popup chevron -> background = popup fill
    - progress fill -> background = track fill
  Prefer a single surface with a 1px accent border over nested 2px rings; the
  nested approach exposes tiny seams at the arc/straight-line junctions.

4. Do not draw wider than the allocated widget
----------------------------------------------
Symptom:
  The Preview button appeared cut off on the right in a narrow/scaled window.

Cause:
  RoundedButton painted to its requested width instead of the width the grid
  actually allocated. If the allocation is smaller, the right edge is clipped
  and looks square.

Rule:
  - Bind <Configure> on every custom Canvas control and repaint.
  - Paint to winfo_width() when it is greater than 1; use the requested width
    only before the first layout.
  - Add responsive breakpoints so controls do not have to shrink below their
    text width:
      < 740px content: URL actions move under the field
      < 820px content: Preview stacks under Options

5. Card sizing and equal-height cards
-------------------------------------
Symptom:
  The Preview card was much taller than Options; later an empty-state frame
  disappeared inside a zero-height body. Queue rows with wrapped titles had
  their status line clipped at the card's bottom edge.

Cause:
  - A Canvas has a large default requested size unless explicitly constrained.
  - Autosize Cards forced the body window's height to the card's current
    height. Content growth therefore never produced a body <Configure> event,
    so the card stayed at whatever height it had when the window last resized.
  - A footnote inside the Options grid row made the Preview stretch taller.

Rules:
  - Autosize cards must set only the body window's width on Configure and let
    the body keep its requested height. The body <Configure> handler then
    resizes the card for both growth and shrinkage.
  - Do not pin the body height for autosize cards; it hides every content
    reflow. Set the height explicitly only for autosize=False cards.
  - For a fill-to-row card, set autosize=False and height=1 so the grid row
    (driven by the Options card) determines the height; pack with
    fill="both", expand=True.
  - Keep footnotes outside the two-card grid row.
  - Stacked mode must assign the Preview card an explicit height equal to
    Options.

6. Do not let a fitting page scroll
-----------------------------------
Symptom:
  Content could be wheel-scrolled even when everything fit, leaving blank
  space above the URL row.

Cause:
  ScrollFrame handled wheel events even when the scrollbar was hidden.

Rules:
  - Ignore wheel events when content fits.
  - Force yview_moveto(0) whenever the scrollbar is hidden.
  - Test by scrolling up aggressively at a size where content fits.

7. Dropdown menus need explicit dismissal
------------------------------------------
Symptom:
  The quality list stayed open until an item was selected and floated above
  other applications.

Cause:
  The native tk.Menu popup did not provide predictable click-away/focus-loss
  behavior in this environment.

Fix:
  PopupSelect now uses a custom overrideredirect Toplevel:
  - closes on outside click (local grab)
  - closes on Escape
  - polls focus and closes when the app loses focus
  - closes on selection
  - focus stays on the control, so keyboard Up/Down/Return still work
  - position is clamped to the screen

Rule:
  For small desktop utilities, prefer a custom dropdown when dismissal and
  focus behaviour matter. Test click-away and app switching explicitly.

8. Window chrome and cursors
----------------------------
- Keep the native GNOME title bar. Do not fake macOS traffic lights or hide
  the title bar; Wayland dragging/resizing becomes fragile.
- Do not set hand/xterm cursors on custom controls. Use system defaults.
- One gray palette plus one blue accent is enough; reserve red for errors.

9. Layout/style checklist
-------------------------
- Native title bar is the only top bar; no in-app title toolbar.
- URL field + Preview + Download in one row on wide windows.
- Preview/Download on a second row below the field on narrow windows.
- Options and Preview cards always equal height.
- Queue below, status bar at the bottom.
- Status text only while downloading or after an error; no permanent "Ready".
- Disabled primary buttons: gray fill, muted icon, gray label.
- Preview loading/placeholder backgrounds: gray, never green.
- Use fonts: Adwaita Sans -> Cantarell -> Noto Sans, with point sizes.

10. Verification matrix
-----------------------
Run tests with both interpreters:
  python3 -m compileall -q tubegrab.py tubegrab tests
  python3 -m unittest discover -s tests
  /usr/bin/python3 -m unittest discover -s tests

Manual screenshots:
  TUBEGRAB_THEME=light python3 -m tubegrab
  TUBEGRAB_THEME=dark  python3 -m tubegrab

Sizes:
  1040x700, 900x620, 800x620, 640x600

Check:
  - text is smooth (Xft)
  - rounded corners have no square seams/fringes
  - Preview height equals Options
  - long queue titles wrap and keep the status line/progress bar inside the card
  - queue thumbnails are letterboxed, never cropped
  - no scrollbar when content fits
  - quality slider fits all nine steps at 900px and never opens a popup
  - audio modes hide the quality slider and container row
  - disposable partial downloads show Retry and Start over
  - no green in normal/success states
  - disabled Download is gray

On this desktop, screenshots can be captured with:
  DISPLAY=:0 magick import -window <window-id> out.png
Use xprop -root _NET_CLIENT_LIST to find the window id.

11. Build / release
-------------------
Per-user install:
  ./install.sh

Fedora RPM:
  ./packaging/build-rpm.sh
  sudo dnf install dist/tubegrab-1.3.0-1.fc45.noarch.rpm

The RPM installs:
  /usr/bin/tubegrab
  /usr/share/tubegrab/tubegrab/
  /usr/share/applications/tubegrab.desktop
  /usr/share/icons/hicolor/.../apps/tubegrab.*

The RPM launcher uses /usr/bin/python3 and PYTHONPATH=/usr/share/tubegrab.
The RPM is a noarch package and requires python3-tkinter, yt-dlp, and
/usr/bin/ffmpeg.

12. Known limitations
---------------------
- Tk has no backdrop blur or CSS box shadows; the UI approximates depth with
  borders and flat fills.
- Canvas controls are custom widgets, so screen-reader support is limited to
  ordinary focus/keyboard behaviour.
- Text quality depends on the interpreter's Tk/Xft build.
- Wayland fractional scaling may affect screenshot-based pixel inspection.

13. Tk 9 centres undersized scroll regions
------------------------------------------
Symptom:
  After the first window resize, the page padding collapsed to zero on the
  left and did not come back when the window grew again. The top padding was
  also never visible.

Cause:
  ScrollFrame used bbox("all") as its scrollregion, and that rectangle starts
  at the padding offset, e.g. (24, 14). Tk 9 centres a scrollregion that is
  smaller than the viewport, so canvasx(0) became 24 and cancelled the left
  padding. yview_moveto(0) put the viewport top at y=14, hiding the top padding.

Fix:
  Build the scrollregion explicitly as
    (0, 0, max(canvas width, bbox right), max(canvas height, bbox bottom))
  and recompute it in both the inner and canvas <Configure> handlers.

Rule:
  Never use bbox("all") directly as the scrollregion when the inner window is
  inset by padding. Anchor the region at (0, 0) and make it at least as large
  as the viewport.

14. Prefer a segmented slider over a popup for short option sets
----------------------------------------------------------------
Symptom:
  The quality dropdown could stay open or float after focus changes, and its
  popup made a frequently changed setting feel heavier than the rest of the UI.

Cause:
  A popup Toplevel has to manage grab, outside clicks, Escape, focus polling,
  and screen-edge placement. Those paths are easy to get wrong and do not
  match the segmented pickers already used for Format and Container.

Fix:
  - Replaced the quality dropdown with a full-width SegmentedControl.
  - Added a stretched layout mode that distributes measured segment widths
    across the allocated card width.
  - Kept Left/Right, Home/End, click selection, and a 1px accent focus outline.
  - Removed PopupSelect entirely so there is no floating window to dismiss.
  - Added a Container segmented picker and codec/container lines in Preview.

Rule:
  Use a segmented control or slider for small, frequently changed option sets.
  Reserve a custom Toplevel dropdown for long menus where a segmented track
  cannot fit every label legibly.
